# 内部周报排版使用手册

本 skill 把本地文稿、封面和图包排成公众号正文，支持离线图片复制与自建图床直链复制。
安装后向 Agent 说明“使用 wechat-weekly-layout 排版本期周报”，并主动提供下面的资料。

## 一次性准备

安装本 skill 和 `requirements.txt` 中的 Python 依赖。图床方案还需管理员提供：
图床 HTTPS 地址、登录账号或 API Token 的使用方式，及保存凭证的位置。
这些参数由使用者本机保存，不写入 skill 文件，不提交仓库，不随预览分发。

图床管理员可以统一创建一个普通上传账号、生成 Token 并通过内部安全渠道分发。
成员把同一 Token 配置到各自的本机环境变量 `ZIPLINE_TOKEN`、系统钥匙串或私密文件。
Token 不需要发送给聊天中的 Agent；告知其变量名、钥匙串引用或文件路径即可。
共享账号会共享图库及图片修改/删除权限，需要按人员隔离时分别开户。
共享 Token 轮换后，所有使用该 Token 的成员都需更新本机配置。

网页登录用于人工上传、整理相册/文件夹和生成 Token；自动排版上传使用 API Token。
不要把管理员密码分发给编辑成员。

## 每期提交模板

复制下面模板并填写；**主动提供本期推荐阅读的周报链接和留言板链接，以及 Staff**。

```text
使用 wechat-weekly-layout 排版公众号周报。

期号、日期：
原稿文件/目录：
图片素材目录：
本期文章封面：
排版参考文章/HTML（有指定样式时提供）：

图片方案：自建图床 / 纯本地复制
图床产品与版本（图床方案必填）：
图床 HTTPS 公网地址：
内网上传地址（可选）：
登录方式：API Token / 网页账号（需协助生成 API Token）
凭证位置：环境变量名 / 钥匙串引用 / 本机私密文件路径
图床文件夹：周报-<期号>

推荐阅读：
- 往期周报：标题、链接、封面或读取来源
- 留言板：标题、链接、封面或读取来源
如不放某项，请明确写“不放”。

Staff：
文案：
文案审核：
排版：
其他分工（可选）：

需要注意的图片顺序、折叠/横滑、特殊文字：
```

本地复制不需要图床信息。资料不全时 Agent 会集中提醒缺项；图片归属不清、推荐链接缺失、
Staff 未确认时，不会用旧期内容或猜测值补齐后声称完成。

## 审稿与复制

1. 核对本期期号、封面、每条新闻与图片顺序、推荐阅读和 Staff。
2. 纯本地方案打开 `output/preview.html`；图床方案打开 `output/preview-hosted.html`。
3. 点击“复制公众号正文”，粘贴到微信编辑器。图床方案需保持网络可用。
4. 等待图片导入完成，保存草稿，再重新打开检查图片与手机预览。
5. 格式不兼容时试“兼容复制”；它会展开所有图片，图片来源与当前预览模式一致。

图床版保留本地视觉预览，但剪贴板中是图片直链，不会带上 API Token。
图片直链允许知道地址的人读取，适合计划公开发布的配图。图床上传成功并不等于微信已转存成功。

## 常见情况

- **未登录不能上传**：确认账号/API Token 仍有效，Token 原值不加 Bearer。
- **图床能看，微信失败**：检查直链在未登录窗口能否打开、是否被验证码/防盗链拦截，再看图片大小与格式。
- **上传中断**：保留上传映射，重新执行可核验并复用成功图片，勿先删缓存。
- **换图后仍显示旧图**：重新 render 再上传，内容哈希变化后会产生新图片地址。
- **成员离开或 Token 泄露**：由管理员轮换对应普通账号的 Token，通过原安全渠道更新成员配置。
