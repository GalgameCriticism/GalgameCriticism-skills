# 知乎图文文章适配说明

## 连接、导入与恢复

用隔离会话的页面账号信息或 `/api/v4/me` 返回的昵称与账号 ID 核验身份；只记录公开身份，不输出完整响应。CDP 端口是运行时配置，不能硬编码到团队 skill。

导入入口是角色为 button、名称为“导入”的按钮，随后是 `aria-label="导入文档"` 的按钮；后者可能有 MD/Doc 子元素，纯文本精确定位不一定匹配。通过接受 `.docx,.markdown,.mdown,.mkdn,.md` 的 file input 传入嵌图 DOCX。等“文档导入中”退出并确认所有正文图片托管在 zhimg HTTPS 地址上，不能因入口点击成功就提前发布。

原图过大时先压缩派生图片再生成 DOCX，按当前 UI 限制留出余量。图片数量和正文嵌图关系必须完整；会话在大文件导入时断开，先按共享规则恢复同一 profile，再打开原草稿，重新检查已有内容，必要时在该草稿重新导入合规 DOCX。不得删 profile、换登录态或新建重复文章。

编辑器校验使用正文容器而不是全页 `innerText`；排除明确的图片注释 UI 占位说明，再逐字比较归一化全文。封面使用本期指定图片，通过 `.UploadPicture-input` 上传并等到封面显示 zhimg URL，不能复用上一篇封面。

## 提交与公开页

精确点击编辑器“发布”一次，监听 `/api/v4/content/publish` 并核实应用结果及公开文章 ID，保留提交前状态。响应/URL 转换与 `https://zhuanlan.zhihu.com/p/<id>` 建立对应后回读公开页面。只有请求 HTTP 200、没有公开 URL 或仍是草稿时，不能记成功。

公开正文常位于 `.Post-RichTextContainer .RichText`；核对作者、完整标题、来源、归一化全文、全部正文图片及顺序。知乎图片 URL 的 host、`_r`/`_720w` 等规格可变；按已核验的 `v2-<hash>` 图片标识比较原序号，不把 URL 字符串变体误报为顺序错误。封面不计入正文图片数。

回执保存公开 `url`、全文核验、图片数量和图序核验；最终回复直接输出 `[知乎本期文章](实际公开url)`。结果未知先查询原草稿/管理页，不再次点击发布。

## 旧 MCP 的兼容边界

上游仓库：<https://github.com/Victorzwx/zh_mcp_server>

当前版本的发布入口名为 `create_atticle`（上游项目保留该拼写），输入包括：

- `title`：文章标题。
- `content`：正文。
- `images`：可选图片参数，当前发布器按封面图片使用。
- `topic`：可选话题。

当前仓库不应保存 `zhihu_cookies.json`、Chrome 用户目录、验证码或发布回执中的私密字段。上游接口返回成功后仍需回读文章页面确认作者和内容状态。
